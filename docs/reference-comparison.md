## Accuracy and freshness

Both applications use provider-reported values instead of counting conversation tokens as a substitute for subscription allowances. The reference defaults to 15-minute polling (`app_settings.rs`); TokenFuel defaults to two minutes and respects per-account backoff and provider retry instructions. Neither can promise instant or uninterrupted counters during provider delays, outages, rate limiting or expired sessions. TokenFuel preserves cached values with visible stale/error states and never synthesizes a missing denominator/reset date. Codex credit balances have no remaining percentage unless a real ceiling exists; the reference additionally maintains an observed credit baseline.

This review also fixed Codex pin identity: a weekly pool retains its identity when the provider moves it from secondary to primary. Unknown or duplicate-duration pools remain separate, rather than being merged. Existing preview pins using old slot IDs may need re-pinning in expanded details; missing pins remain unavailable instead of silently selecting another pool.

This review found and fixed two Claude parsing gaps in TokenFuel: `utilization` as an alias in newer scoped entries, and distinct stable identities for non-model scopes. Regression tests cover reordered workspace quotas so pins and alerts cannot silently select another pool.

## Compact visibility

Slim Strip and Mini Rings show enabled, consented account connections, not one placeholder for every supported provider. Two enabled accounts produce two tiles. Offline, expired or stale connections stay visible so failures do not disappear. With none enabled, one configured Codex account (otherwise the first configured account) stays visible with Connect; even deleting every account leaves a single unconfigured tile leading to Settings. Disabled cached counters are not rendered. No credential or session is read merely to choose this fallback.

Logical widget surfaces: one/two/three accounts use 214/380/546-pixel strips or 144/240/336-pixel rings, height 84/116. More accounts wrap and scroll within a bounded area. Native transparent margins add 12 pixels to width/height. Settings expand to 540 pixels and closing them restores the compact width. Browser previews add a sample/preview disclosure absent in native builds. Full account/workspace, source, observation age, exact amounts and reset details are in tooltips/expanded limits.

Remaining release checks: Gemini native sign-in/reload; real Claude enterprise payload comparison; Windows display scaling, multi-monitor drag/snap, tray, startup and alert interactions. See [office validation](office-validation.md). These gaps do not qualify as verified automatic support.
