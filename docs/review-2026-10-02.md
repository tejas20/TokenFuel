# Review and tracking checks — 2026-10-02

The original preview did not fulfil every integration requirement. This review fixes defects and keeps remaining coverage explicit.

## Fixed findings

- **High: Gemini parser did not recognise the actual Usage page.** The signed-in PRO account uses `/usage` and `usage-metrics-window` with `gxu-currently` and `gxu-weekly`, not a Usage dialog or `/settings/usage`. The parser now reads those quota-only rows. Compared against the live page: 1% used current/five-hour and 0% weekly. Extracted reset labels match the displayed labels; absolute reset timestamps are not fabricated.
- **High: snapshots could look current after ageing or reset.** Native cache and frontend now mark stale readings, preserve error states and show each account's observation age. A newly refreshed account no longer hides an older account's reading age. Provider age labels are retained for Gemini.
- **High: generic capture could merge different quota pools.** Ambiguous periods, duplicate pools, missing percentages, non-percent bars and hidden labels are rejected; pin IDs no longer include DOM ordering.
- **Medium: a missing pinned quota silently selected another pool.** Missing pins now show unavailable rather than replacing the chosen pool with the first counter.
- **Medium: account edits during polling could trigger obsolete alerts.** Revision checks now precede notification delivery and snapshot commit.
- **Medium: Refresh respected local error backoff even after sign-in was repaired.** User refresh overrides local failure backoff, while provider rate-limit Retry-After remains enforced.
- **Medium: unnecessarily repeated snapshot processing and disk writes.** Unchanged disconnected/manual/capture accounts are skipped and configuration/events are written only on a change.
- **Medium: Claude response size was checked after buffering.** Response chunks are now bounded while downloading.
- **Usability: only developer startup was documented.** A prebuilt, checksum-verified launcher and click-to-run installer/portable instructions are now first in the README. Private access still requires GitHub authentication. Application users do not need the developer toolchain.

## Live checks

Two installed Codex app-server reads succeeded, with changing counters during ongoing use. Both returned separate five-hour and weekly pools and provider Unix reset timestamps. The native Codex app's own quota tool returned the same bucket structure. These are Codex pools; ordinary ChatGPT model counters are not certified by that source. No prompts or conversation reads were sent.

Gemini signed-in Usage UI and the exact shipped DOM extraction were compared in the browser, including a page reload and freshness labels. The parser returned the visible 1% and 0% used values, corresponding to 99% and 100% remaining. Its five-hour meaning was confirmed by the visible Information about usage limits explanation. No cookies or session tokens were exported.

A separate opt-in Gemini live WebView source now reloads only `/usage`, waits for a new completed navigation, reads recognised quota rows and requires a recognised provider freshness label. Closing that window, an expired login, unknown markup or failed reload produces an error and retains cached values. This mechanism is experimental: the native isolated sign-in/reload path has not been demonstrated end-to-end on this machine. The browser's sign-in is not shared with the widget.

## Validation and remaining coverage

Local validation passed: 15 Rust tests, 10 frontend tests, strict TypeScript/Vite build, Rust formatting and Clippy with warnings denied. Windows packaging is rebuilt from the reviewed source. Regression fixtures include the observed Gemini markup, used/remaining orientation, duplicate scopes, missing/hidden values, freshness, reset expiry and cached connection errors. The previous baseline's two GitHub Windows CI runs passed.

Outstanding: native Gemini isolated sign-in and sustained polling; ordinary ChatGPT model counters; Claude personal and Enterprise office payload comparisons; physical monitor/DPI/tray/startup/alerts and live session-expiry/rate-limiting tests. Synthetic tests do not certify these. No source can promise continuously current figures while offline or when the provider stops exposing counters; TokenFuel must show age and unavailable/stale states instead.
Launcher validation: the Windows PowerShell 5.1 cold-download path initially exposed a missing Get-FileHash command. The launcher now uses .NET SHA-256 directly; cold download/checksum/extraction and cached reuse both passed. The wrapper requires no runtime/toolchain install beyond Windows/WebView2 and private GitHub access.
